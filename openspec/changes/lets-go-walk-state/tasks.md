## 1. `lets go records` says which steps are done and which records disagree

All tasks in this section change `lets/src/go/records.ts`, the new `lets/src/go/plan-review.ts` and `lets/src/go/walk.ts`, `lets/src/main.ts` and `tests/go/records.test.ts`, so they run in order. Each test runs `lets` as a program in a temporary Git repository, with a stand-in `gh` and a stand-in `openspec` on `PATH`, as design.md's *Test Seams* says. The spec is `specs/go-records/spec.md`. Design.md decision 1 says which file holds what.

- [x] 1.1 [medium] `lets go records <name>` prints seven keys in order: the four records unchanged, then `done`, `disagreements` and `pull-request`. In a repository with a clean tree, no change folder and no pull request, stdout is exactly `{"plan":null,"review-plan":null,"build":null,"review-build":null,"done":{"plan":false,"review-plan":false,"build":false,"review-build":false},"disagreements":[],"pull-request":null}`. `gh pr view` asks for `number,body,state,isDraft` in its one call, and `pull-request` is the `state` it prints, such as `"MERGED"` (design.md decisions 2 and 3) (verify: node --test --test-name-pattern "a new change|pull-request" tests/go/records.test.ts) (✓ node --test --test-name-pattern "a new change|pull-request" tests/go/records.test.ts passed)
- [x] 1.2 [medium] The `done` answers for plan, build and review build: every step is done when one or more archive folders exist; with no change folder, all four steps are not done and `openspec` is not called; otherwise `openspec instructions apply --change <name> --json` runs once, and `blocked`, `ready` and `all_done` give the answers the spec's *The done key says whether each step is done* lists. A folder that only ends in `-<name>` is not an archive folder (verify: node --test --test-name-pattern "done answer" tests/go/records.test.ts) (✓ node --test --test-name-pattern "done answer" tests/go/records.test.ts passed)
- [ ] 1.3 [medium] Exit 4, with empty stdout and one stderr line that starts `lets go: `, when `openspec` cannot start or exits non-zero, prints something other than JSON with a string `state`, or prints a state other than `blocked`, `ready` or `all_done`; for that last case the line names the state and holds the CLI's `instruction`. A `.openspec.yaml` or `openspec/config.yaml` that exists but cannot be read is exit 4 too (design.md decisions 5 and 6) (verify: node --test --test-name-pattern "fails" tests/go/records.test.ts)
- [ ] 1.4 [complex] Review plan's answer, rules 1 to 4: `true` when an archive folder exists or the change's schema (the `schema:` line of the change's `.openspec.yaml`, then the archive folder's) is `lets-minimal`. Otherwise `true` only when the `review-plan` record is not `null`, the verdict is `APPROVE` or `APPROVE_WITH_CHANGES`, `git merge-base --is-ancestor <sha> HEAD` succeeds, and every commit `git log <sha>..HEAD -- openspec/changes/<name>/ docs/decisions/` lists is a fix, leaving out `tasks.md` only once a line of `tasks.md` in `HEAD`'s tree is a ticked task (`- [x] `), whatever the `build` record says. Covers the spec's scenarios *A lets-minimal change* to *A tasks.md edited in planning and again after the review* (design.md decision 4) (verify: node --test --test-name-pattern "review plan answer" tests/go/records.test.ts)
- [ ] 1.5 [complex] Review plan's answer under `APPROVE_WITH_CHANGES`, rule 5: `true` only when the **Rebuttals** list holds at least as many `Fixed in <commit>:` items as the **Required changes** list holds items, and each named commit is listed by rule 4's `git log` without the `tasks.md` exclusion and changes only paths under `openspec/changes/<name>/` and `docs/decisions/`, read with `git diff --name-only --no-renames <oid>^ <oid>`. Covers the scenarios *Required changes with their fixes* to *A fix from before the review*, including a fix item numbered differently from its required change (design.md decision 4) (verify: node --test --test-name-pattern "required changes" tests/go/records.test.ts)
- [ ] 1.6 [complex] `disagreements` lists, in this order, each matching row as `{"row":<name>,"found":<string>}`: `dirty-tree` (paths from `git status --porcelain=v1 -z` outside `.workspace/`), `change-and-archive`, `archive-not-ready` (`no pull request`, or `isDraft: true` and `no Code review section` joined with `, `, the second only when `openspec/config.yaml` says `lets-standard`), `brainstorm-without-pull-request` (only for a `brainstorm.md` in `HEAD`'s tree), `archive-without-plan-review`, and `null-record` (leaving out review plan on `lets-minimal` and when `archive-without-plan-review` matches). Covers every scenario of *The disagreements key lists the records that disagree* (design.md decisions 2, 3 and 5) (verify: node --test --test-name-pattern "disagreement" tests/go/records.test.ts)
- [ ] 1.7 [easy] `lets go records --help` names `done`, `disagreements`, `pull-request`, `row`, `found`, the six row names, `Check an earlier review` and `lets-review-plan`, as well as every name it printed before, and no longer says the command does not read the schema or decide which steps are done (design.md decision 7) (verify: node --test --test-name-pattern "help" tests/go/records.test.ts)
