## Deviations Ledger

- **1.1 sets `mine: false` in the GitHub adapter and the fake provider.** Task 1.2 and 1.3 own those files, but without the field the type check fails at 1.1's commit. 1.1 gives every candidate `mine: false`, so each commit type-checks; 1.2 reads the real value.
- **The start reads use `<story-name>`, not `<name>`.** In `skills/lets-go/`, `<name>` is the change's name of the run's issue `<i>`. At the start of an epic run, no story is `<i>` yet, so the branch and pull request reads name each story's change name as `<story-name>`, which the Placeholders table already defines as the same text.
- **A failed base edit at the start settles the story as stopped.** The plan says a failed `gh pr edit` is a stop in the story run, but at the start no story run has begun. *Read a pull request's base* returns `edit-failed`, and the start says gh's error and settles the story with `#<story> <story-name>: stopped: <reason>`, then goes on with the next story. Nothing changed in the checkout, so no other stop action applies.
- ***Read a pull request's base* names its results `on-story`, `not-stacked` and `edit-failed`.** `on-story` is not `stacked`: a resumed story stacks on that story only when it is met, which *Take up a started story* checks.
