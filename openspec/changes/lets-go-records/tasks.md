## 1. The `lets go records` command

All tasks in this section change `lets/src/go/records.ts`, `lets/src/main.ts` and `tests/go/records.test.ts`, so they run in order. Each test runs `lets` as a program in a temporary Git repository with a stand-in `gh` on `PATH` that answers `pr view` from a table, as design.md's *Test Seams* says. The spec is `specs/go-records/spec.md`.

- [ ] 1.1 [medium] `lets go records <name>`, in a repository with no commit under `openspec/changes/<name>/`, no folder `openspec/changes/archive/`, and a stand-in `gh` that exits 1 with `no pull requests found for branch "<name>"`, exits 0 and prints exactly `{"plan":null,"review-plan":null,"build":null,"review-build":null}` and a newline, and leaves `git status --porcelain` empty and `HEAD` unchanged (design.md decisions 1, 4 and 6) (verify: node --test --test-name-pattern "a new change" tests/go/records.test.ts)
- [ ] 1.2 [easy] The `plan` record is `{"commit":<%h>,"date":<YYYY-MM-DD>}` of the commit that added `openspec/changes/<name>/tasks.md`, dated by its author date when the committer date differs, and is the same commit after a later commit moves the folder into `openspec/changes/archive/` (verify: node --test --test-name-pattern "plan record" tests/go/records.test.ts)
- [ ] 1.3 [easy] The `build` record is the last commit that modified `openspec/changes/<name>/tasks.md`; it is `null` when no commit changed the file after adding it, and the archive move does not count as a tick (verify: node --test --test-name-pattern "build record" tests/go/records.test.ts)
- [ ] 1.4 [medium] The `review-build` record is the commit that added `openspec/changes/archive/<YYYY-MM-DD>-<name>/tasks.md` with `pr` from `gh pr view`, or `"pr":null` when `gh` finds no pull request; it is `null` for a folder that only ends in `-<name>`, for two matching folders, and for a folder no commit added (verify: node --test --test-name-pattern "review-build record" tests/go/records.test.ts)
- [ ] 1.5 [complex] The `review-plan` record comes only from the body's `## Plan review` section, up to the next `## ` line: `commit` is the `Reviewed: ` value as written, `verdict` the `- **Verdict:** ` value, `date` the named commit's author date and `pr` the number. It is `null` with no pull request, no section, a missing or empty line, a value that is not 4 to 40 hex characters (`HEAD`, `--all`), or a hash git cannot find. A `Reviewed:` line in a **Code review** section is never read (design.md decision 3) (verify: node --test --test-name-pattern "review-plan record" tests/go/records.test.ts)
- [ ] 1.6 [medium] A missing name exits 2 with Commander's missing-argument error, and a name that is not lower-case kebab-case, such as `../lets-go-chore`, exits 2 with `lets go: ` and the name before any `git` or `gh` call. A `gh` failure other than no pull request, `gh` output that is not the expected JSON, and a folder outside any Git repository each exit 4 with one stderr line that starts `lets go: ` and names the command and its error. Stdout is empty in every case (design.md decision 5) (verify: node --test --test-name-pattern "fails" tests/go/records.test.ts)
- [ ] 1.7 [easy] `lets go --help` names `questions` and `records`, and the group's description says it reads the settings and records `lets-go` uses. `lets go records --help` names `plan`, `review-plan`, `build`, `review-build`, `commit`, `date`, `pr`, `verdict`, `null`, `tasks.md`, `Plan review` and the exit codes `0`, `2` and `4` (verify: node --test --test-name-pattern "help" tests/go/records.test.ts)
