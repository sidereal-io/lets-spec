## 1. The lets go step-prompt command

Every task in this section adds tests to `tests/go/step-prompt.test.ts` and code to `lets/src/go/step-prompt.ts`. The command is registered in `lets/src/main.ts`. The `go-step-prompt` spec in this change gives each scenario, and design.md says where the text and the flag table live. The tasks share files, so they run in order.

- [ ] 1.1 [medium] `lets go step-prompt --for <step>` for `plan`, `review-plan`, `build` and `review-build`, with `--name`, `--issue`, `--issue-url`, `--schema`, `--route` and `--questions`, exits 0 and prints the walk step's two header lines, then `## What to run` with the step's one skill sentence, `## Writing`, `## Questions` and `## The report`, in that order, ending in one newline. It writes no file, and calls no stand-in for `gh`, `openspec` or a resolver CLI. (verify: `node --test tests/go/step-prompt.test.ts`)

- [ ] 1.3 [medium] `## Questions` holds `The question mode is <mode>.` and the rules for auto, ask, `needs-input`, confirmations and `## Answers`. `## The report` holds the three `step-report` examples and the evidence and quoting rules. ## 2. lets-go runs the command [depends-on: 1]

- [ ] 2.1 [medium] *Run a step* in `skills/lets-go/SKILL.md` creates `.workspace/lets-go`, runs `lets go step-prompt --for <step>` with the values each kind of step passes, quoted for the shell, and sends stdout to `.workspace/lets-go/<session>-prompt.md`.
