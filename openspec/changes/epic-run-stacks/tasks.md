## 1. `lets backlog ready --met-blockers`

The tests drive `lets backlog ready` through `run([...], deps)` in `tests/lets/backlog/ready.test.ts`, with fake `gh` rows from `tests/lets/backlog/fixtures/fake-gh.ts`, and `ready()` directly in `tests/lets/backlog/policy.test.ts`. The new search's row returns `blockedBy` as `{ nodes: [{ number, state, title, url }], totalCount }`, the shape `gh` prints today (design decision 2).

- [x] 1.1 [medium] `ready()` in `lets/src/backlog/policy.ts` takes a `met` list of keys. A candidate that is not `free` but whose `blockers` (a new `Candidate` field: the keys of its open blockers, or `null` when any is in another repository, and `null` for a candidate the adapter's blocked search did not return, such as an assigned issue) are all in `met` passes the blocker filter, and still needs Status Todo, a Kind that is not Epic and a ranked Priority. A `null` `blockers` never passes. The comment on `Candidate` in `lets/src/backlog/adapter.ts` states both `null` cases, and that `created` may be `''` only for a candidate that is neither free nor in the blocked search. With no `met`, the result is today's (verify: node --test tests/lets/backlog/policy.test.ts) (✓ node --test tests/lets/backlog/policy.test.ts passed)
- [x] 1.2 [medium] `lets backlog ready --met-blockers 279` lists #280, an unassigned Todo Must story whose only open blocker is #279. The GitHub adapter runs its second search, `issue list --search is:open no:assignee is:blocked --limit 500 --json number,createdAt,blockedBy`, only when the option is given; without it, the calls are exactly today's. Each blocked candidate's `created` comes from that search's `createdAt`, so #280, Must and created before a free Must story, is listed before it. #281, blocked by #279 and #280, is not listed with `--met-blockers 279`; #282, blocked only by #279 and assigned to `octocat`, is not listed; a story blocked by `other-org/tools#279` is not listed either (verify: node --test tests/lets/backlog/ready.test.ts) (✓ node --test tests/lets/backlog/ready.test.ts passed)
